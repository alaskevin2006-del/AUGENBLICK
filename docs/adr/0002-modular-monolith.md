# ADR-0002: 模块化单体 + 引擎注册表（否微服务）

- 状态：已接受
- 日期：2026-08-25
- 决策人：恺欣

## 背景

早期可能倾向「每个引擎一个微服务」。但当前规模为几十到几百活跃学习者，微服务运维成本远超收益。

## 决策

V1 采用**模块化单体 + 引擎注册表**：一个 Web 前端、一个模块化后端、一个数据库 + 统一事件日志、一个对象存储/CDN、一个内容编译任务。5 引擎 + Direct 保留位通过注册表作为模块接入。

## 理由

符合「四层架构」与「API 权威」红线；比多套独立服务更适合当前规模；模块化保证将来需要时可拆。

## 影响面

- 平台腿后端：模块边界清晰即可，不必拆服务。
- 唯一例外：Companion 语音分析未来确有独立算力需求时再拆。

## 后果

- 利：部署简单、事务一致、上下文简单。
- 弊：模块耦合风险需靠「五方状态归属」纪律约束。
- 回看点：规模化后若某模块成为瓶颈，再评估拆分。
