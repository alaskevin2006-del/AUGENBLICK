# ADR-0009: 学习/测试模式的完成与尝试判定

- 状态：已接受
- 日期：2026-08-25
- 决策人：恺欣

## 背景

AUGENBLICK.md 五处 `[assumption — confirm]` 需逐条定死，涉及单元解锁、完成判定、逃逸机制、测试重考，直接影响编排器与学习状态的实现。

## 决策（五项最终判断）

**① 单元解锁门槛 —— 可配置，非全平台固定规则。**
由课程开发者按课程/场景决定是否设、设多少。区分三个概念：
- 执行完成 = 程序到达 Excel 最后一行
- 通过 = 满足课程开发者配置的分数条件
- 解锁 = 按该课程的通过条件决定

**② 完成 = 脚本末行执行完 —— 成立。**
MVP 不附加「所有活动必须成功」「必修不得跳过」等复杂状态机。

**③ 三轮逃逸 —— 仅学习模式成立。**
学习活动完成三个完整循环后显示跳过出口；跳过后：当前活动结束、记录为跳过/放弃、未掌握内容进错题记录、程序继续后续行。**测试模式不适用**（测试不可跳过）。

**④ 中断测试整份重发 —— 成立。**
「提交才算一次尝试」区分：
- 打开测试 ≠ 尝试
- 中断 ≠ 尝试
- 整份重发 ≠ 重考
- 正式提交 = 消耗唯一一次尝试
- 提交后再次参加 = 重考（当前不允许）

MVP 接受「提交前无限重启」风险，记录为后续问题（非定义上的重考）。

**⑤ 部分分半填充段 —— 成立。**
部分分（Ekspert/Sokole Oko）渲染为半填充进度段：金色填充到得分比例、超出部分红色。

**如实记录但不阻塞**：答题失败、学习跳过、测试中断重开、技术执行失败、提交及分数，全部记录还原事实，不自动变成阻塞条件；唯「测试主动跳过」除外（测试明确不可跳过）。

## 理由

- 完成判定保持简单，避免过早引入复杂状态机。
- 「提交才算尝试」同时满足「测试不可重考」与「中断整份重发」两句，消除表面矛盾。
- 门槛可配置把控制权交给课程开发者，而非平台一刀切。

## 影响面

- 编排器：完成/通过/解锁三态判定；逃逸出口仅学习模式注入。
- 学习状态：尝试计数以「提交」为准；中断重发不计数。
- 外壳：跳过出口仅学习模式显示。

## 后果

- 利：语义清晰、实现简单、无表面矛盾。
- 弊/边界：若课程设最低分门槛 + 测试不可重考，学习者提交未达标后将无法再满足通过条件。此为现有要求的直接边界，**不擅自补重考/补考/管理员解锁**，记录为未决（OPEN-QUESTIONS #11）。
