# 架构文档（ARCHITECTURE）

> 全项目架构的唯一地图。各引擎 AI 开工前必读。

## 一、定位：学习操作系统

AUGENBLICK = **学习操作系统**，不是引擎的入口页，也不是万能题库。

- 学习者看到：课程、目标、进度、练习、反馈。
- 课程开发者看到：课程结构、内容库、校验、预览、发布。
- 引擎只是平台内部按活动调用的专业能力。
- Polyglot / Savant = 同一软件（AUGENBLICK）的两个品牌站点：不同域名、不同 logo、不同内容目录；引擎与格式完全相同（见 ADR-0006）。账户互通性待定。

## 二、系统结构：模块化单体 + 引擎注册表

- 一个 Web 前端：统一 Shell + 设计系统 + Activity Host。
- 一个模块化后端：账户、课程、编排、学习状态、发布、分析。
- 一个数据库 + 统一事件日志。
- 一个对象存储 / CDN（图片、音频、视频、掩膜）。
- 一个后台内容编译任务。
- 仅 Companion 语音分析未来确有独立算力需求时，才拆单独服务。

数据流：

```
Excel/JSON/媒体 → Course Studio(导入·校验·预览·评审)
  → 不可变 Course Version(规范化内容 + 资产清单)
  → Session Orchestrator → 统一 Activity Host
  → 引擎(Znawca/Anvil/Ekspert/Sokole Oko/Companion/Direct 保留位)
  → Learning State(掌握度·错题·事件·分析)
```

## 三、五方状态归属

| 组件 | 职责 |
|---|---|
| 引擎 | 呈现活动、理解专业数据、给出领域评分证据 |
| 编排器 | 活动顺序、题集固定、随机种子、中断恢复、失败处理 |
| Learning State | 掌握度、间隔复习、混淆关系、跨会话历史 |
| Shell | 导航、进度、统一反馈、语言、音频与无障碍偏好 |
| 内容流水线 | 导入、校验、编译、版本、发布、回滚 |

## 四、三层内容模型

课程发现（第一层 xlsx）→ 课程脚本（第二层 xlsx，一行 = 一个活动，B 列指定引擎）→ 引擎数据（第三层，各引擎私有）。

- Excel = 批量创作与交换格式；运行时读「不可变 Course Version」，不直接读 Excel。
- 第三层对编排器不透明，仅暴露 package/checkpoint、itemCount、(Companion) 声音版本约定。

## 五、引擎统一合约（三份）

内容编译合约 + 运行时合约 + UI 宿主合约。详见 `docs/合约.md`。

## 六、红线

1. 逻辑全走 API，不进浏览器。
2. 合约唯一（根 `docs/合约.md`），各引擎只实现、不复制。
3. V1 纯 Web，不做 PWA。
