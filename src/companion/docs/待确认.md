# Companion 待确认问题清单

> Companion 引擎特有的未决事项。每项含「问题描述 + 参考做法 + 状态」。解决后：引擎内部决策写 `docs/adr/`；跨引擎 / 需客户拍板回报规划总控，进根 `docs/OPEN-QUESTIONS.md`。
>
> 状态取值：`已定参考`（文档已有答案，实现时落地即可）/ `待定`（本引擎内定，标记切片期或实现期）/ `待确认`（边界归属需与平台腿对齐）/ `待客户`（需恺欣向客户澄清）/ `待评估`（合规评估）。

## A. 职责范围

### A1. Companion 管什么、不管什么？
- 问题：职责边界是否就是「逐行脚本执行器」这一句，有无隐含的进度/数据职责。
- 参考做法：COMPANION §10 明确「只覆盖脚本执行器」，**不覆盖**上层导航（checkpoint/单元/课程管理）、脚本创作工具、音频生成、学习者进度追踪与分析；ARCHITECTURE「五方状态归属」进一步划死——引擎只负责「呈现活动 + 理解专业数据 + 给出领域评分证据」，顺序/题集/恢复/调度归编排器，掌握度/错题归 Learning State。
- 状态：已定参考

### A2. Companion 的 UI 归谁？
- 问题：频谱叠加、音高曲线、节奏分割等独有可视化是引擎 UI，还是 Activity Host 的插件。
- 参考做法：ADR-0003 统一走 Activity Host（主题/尺寸/焦点/键盘/RTL/媒体权限/暂停/退出确认/错误界面）；引擎模板 `src/_template` 保留 `ui` 目录，说明引擎自带答题 UI，但须在 Host 约束下用 mount 接口挂载（非 iframe）。独有可视化属引擎 UI，媒体权限/暂停/退出确认/键盘由 Host 统一。
- 状态：待定（写 UI 时定）

### A3. 录音/播放与语音分析分别在浏览器还是后端？
- 问题：3 秒倒计时、VAD 静音检测在客户端还是服务端做。
- 参考做法：红线「逻辑全走 API，不进浏览器」+ COMPANION §9 推荐库全 Python + ADR-0007（Django+Celery）。方向：录音/播放/倒计时/VAD 在浏览器（Host 管麦克风权限），评分/频谱/音高/节奏分析全在后端 Celery worker。
- 状态：待定（实现时定）

## B. 输入输出约定

### B1. 第三层脚本（A–Q 列）与第二层脚本（A–H 列）的关系？
- 问题：两层 Excel 易混淆，需明确 Companion 读的是哪一层。
- 参考做法：AUGENBLICK §3.2 第二层脚本 B 列指定引擎、C 列 File Called、D 列 Package/Checkpoint；Companion 属「渐进式引擎」，D 列数字 = 从该 checkpoint 起播。第三层（A–Q 列）是 Companion 私有、对编排器不透明，只暴露 package/checkpoint、itemCount、声音版本约定（§3.4 / ARCHITECTURE 四）。
- 状态：已定参考

### B2. 运行时读源 Excel 还是读编译产物？datasource 接口怎么定？
- 问题：COMPANION §8 原文「读文件系统 + 按文件名前缀匹配」与 ADR-0004 冲突，需改为读编译产物。
- 参考做法：ADR-0004「Excel = 交换格式，运行时读不可变 Course Version（稳定 ID）」；引擎模板有 `datasource` 目录，需抽数据源接口（同 Znawca 的 `node:fs → 数据源接口` 改造）；音频从对象存储签名 URL 加载（ADR-0008）。
- 状态：已定参考（实现时落地）

### B3. 预执行校验（音频缺失、E/G/J/L/N/P 多列冲突）由谁做？
- 问题：COMPANION §3 的引擎自校验是否上移到平台内容流水线。
- 参考做法：平台已有三级校验（AUGENBLICK §7 Layer 1 上传单元格级校验 + Layer 2 预飞 + Layer 3 运行时告警）；文件存在性/互斥规则属「内容正确性」，应进 Layer 1 流水线；引擎运行时只读编译产物，不应再重复读文件系统做存在性检查。
- 状态：待确认（与平台腿对齐归属）

### B4. 语音输入（H 列）怎么产出 0-1 score 和 dimensions[]？
- 问题：准确率评分公式、音素·节奏·语调三轴如何量化。
- 参考做法：合约.md 已定「score 0-1 + dimensions[]（音素·节奏·语调）+ masteryEvidence」；COMPANION §9 给出技术路线（DTW 对齐 + 频谱相似度 + Parselmouth 音高/强度 + MFA 音素切分），但**具体评分公式/阈值未定**（根 OPEN-QUESTIONS #2，切片期需定）。
- 状态：待定（切片期定）

### B5. Companion 是 scored engine 吗？H 列 L/T 语义？
- 问题：baseline 适用列含 H（L/T），但需求 §3.2 H 列「all scored engines」、Companion 归「渐进式引擎」，未明确 Companion 是否有 L/T 及 mode 含义。
- 参考做法：Companion 产出 score 0-1 + dimensions[]（音素·节奏·语调），属 scored；但 L/T 的学习循环（答错重抽）对逐行脚本语义不明，需平台统一。
- 状态：待确认（与平台腿对齐）

## C. 与其他引擎/平台的接口依赖

### C1. 如何接入三份统一合约？
- 问题：Companion 适配器各要暴露哪些能力。
- 参考做法：合约.md v0.3（草案，待 Znawca 切片后冻结）：内容编译合约（`capabilities/parse/validate/compile/estimateItemCount/migrate`）+ 运行时合约（调用包 JSON → 四事件，事件带 eventId/序号/时间戳）+ UI 宿主合约。Companion 只实现、不复制。
- 状态：已定参考

### C2. Companion 的 itemCount（Questions bar 段数）怎么算？
- 问题：Companion 无 G 列（Number of Questions），题数来源。
- 参考做法：AUGENBLICK §8「for Companion，one segment per section between one vocal input and the next」；需通过 `estimateItemCount`（内容编译合约）在 `activityReady` 时上报，让 Shell 提前画 Questions bar。
- 状态：待定（实现 estimateItemCount 时定）

### C3. `_M/_F` 性别文件怎么解析？
- 问题：「性别 → 角色/语法/声音版本偏好」语义待客户澄清。
- 参考做法：AUGENBLICK §4.3 已定解析规则（C 列 basename → `<name>_M.xlsx`/`<name>_F.xlsx`；缺变体回退可用变体 + 提阻塞错误；发布前校验两变体都在；学习者性别注册时声明、不可自改）。但「性别对应什么角色/语法/声音」改了客户原始需求，标根 OPEN-QUESTIONS #7。
- 状态：待客户

### C4. checkpoint 导航 + 「Click to continue」如何与编排器衔接？
- 问题：「Click to continue」是否就是 `activityFinished` 信号；checkpoint 起播时显示状态如何重建。
- 参考做法：COMPANION §2/§7 编排器可指定 checkpoint 起播，末行执行完显示按钮、等学习者按下才返回上层（Unit-tier）；§4 Q 列「checkpoint 起播须先扫从头到目标行、重建显示状态（不播音）」。需确认这套重建逻辑与 `activityReady`/恢复 token 的对齐。
- 状态：待确认

### C5. 中断恢复（resume token）粒度？
- 问题：Companion 恢复 = 活动起点重播，还是精确到 checkpoint/某行。
- 参考做法：AUGENBLICK §5.4「中断后重开当前活动从头（学习模式 mastery 丢弃）」；Companion 的全局暂停/practice 暂停是引擎内交互，与平台层「活动级恢复点」是两层，调用包含 resume token（合约.md）。粒度待定。
- 状态：待定

## D. 部署与运行环境

### D1. 技术栈与语音分析库怎么落位？
- 问题：MFA 等重依赖模型的打包与 worker 镜像。
- 参考做法：ADR-0007 已定 Django 5.2 LTS（Python 天然适配语音）+ Celery+Redis（转码/语音分析）；COMPANION §9 推荐 Librosa / Parselmouth / DTW(dtw-python/fastdtw) / Montreal Forced Aligner / Silero VAD 五件套，覆盖「加载→频谱→音高/强度→时间对齐→音素切分→实时 VAD」全管线。
- 状态：已定参考（MFA 打包实现时定）

### D2. Companion 语音算力是否要独立服务？
- 问题：MVP 内跑在 Celery worker 是否够用。
- 参考做法：ADR-0002 已定「唯一例外：Companion 语音分析未来确有独立算力需求时再拆」，MVP 不拆微服务、并入模块化单体。
- 状态：已定参考

### D3. 音频媒体存储与加载？
- 问题：每课 E/G/J/L/N/P 前缀音频如何分发。
- 参考做法：ADR-0008 已定媒体走对象存储 + 短期签名 URL/CDN，付费课程 Bucket 不公开；运行时读编译产物 + 资产清单，不读源文件系统。
- 状态：已定参考

## E. 验收与合规

- 参考做法：根 OPEN-QUESTIONS #2（准确率指标待定）、#3（代表课待定）；验收模板要求「合约一致性测试 + 端到端跑通代表课 + 评分归一 0-1 验证」；全局验收叠加「中断恢复≥99.5%、必修静默跳过=0、原始路径/单元格/异常栈进学习者界面=0、可全键盘」（根 `docs/边界与验收.md`）。
- 状态：待定

- 状态：待评估
