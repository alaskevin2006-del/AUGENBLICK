集成与平台提案
开发者规格说明书
文档目的：Augenblick是一个基于订阅的在线语言培训平台。六个教学引擎已经存在，作为具有完成视觉皮肤的独立程序运行。本文档不重新规约这些引擎。它规约的是围绕它们的平台：用户账户、课程目录、决定何时运行什么的电子表格驱动脚本系统、共享进度显示、评分、验证和管理。
以下所有内容面向程序员编写。凡是有意留给开发者决定的地方，标记为[开发者决定]。凡是我用假设填补空白的地方，标记为[假设—需确认]。

1. 本文档范围
范围内：编排器（读取电子表格并驱动引擎的"指挥"）、面向学习者的外壳、账户和支付、管理/创作后台、验证和错误报告、进度跟踪和评分、数据存储。
范围外（由各引擎的单独提案覆盖）：Znawca、Anvil、Ekspert、Sokole Oko、Companion和Direct的内部逻辑和数据格式；题型目录；录音、文字转语音和发音评估；美术和媒体制作。
关键依赖：引擎已存在，但其实现技术未在本文档中记录。编码开始前，开发者必须对每个引擎进行盘点（语言、框架、如何加载数据、是否可以嵌入页面），并确认§4中的两种集成策略哪种适用。

3. 内容模型：三个层级
3.1 课程发现（第一层文件）
如果主内容文件夹中存在第一层.xlsx文件，则课程存在。文件名既是课程名，也是存放其所有文件和子文件夹的课程文件夹名。
第一层列：A 备注 · B 单元号 · C 单元标题 · D 第二层课程文件的文件名（及匹配子文件夹）。
发布状态。文件的存在使课程成为候选，而非正式产品。每门课程有一个状态：草稿（仅管理员可见）或已发布（学习者可见）。课程包含阻塞性错误时无法发布（§7）。这满足不完整课程可以上传并隐蔽地进行工作的要求。
单元锁定。单元是顺序的：单元n+1在单元n完成时解锁。完成 = 课程脚本的最后一行已执行。[假设—需确认] 进阶不需要最低分数；分数被记录但不限制进度。如果将来需要分数门槛，最简洁的方式是在第一层文件中添加一个可选的额外列（及格线），旧文件可以留空。
3.2 课程脚本（第二层文件）
第1行 = 列标题。第2行 = 课程设计者的永久指南（软件忽略，永不删除）。第3行及以后 = 脚本，严格从上到下执行。一行 = 一个活动。
| 列 | 名称 | 适用于 | 行为 |
| A | Step | 全部 | 步骤标识符/排序。 |
| B | Engine Called | 全部 | 以下之一：Znawca、Anvil、Ekspert、Sokole Oko、Companion、Direct，或保留关键字REVIEW（§6）。 |
| C | File Called | 全部 | 引擎数据文件名；媒体子文件夹同名。 |
| D | Package / Checkpoint | 全部 | 随机引擎（Znawca、Anvil、Ekspert、Sokole Oko）：空 = 从整个题库抽取；数字 = 仅抽取带该包标记的项目。渐进引擎（Companion、Direct）：空 = 从头播放整个脚本；数字 = 从该检查点开始。在所有情况下，空白单元格会引发设计者警告——课程仍会运行，但遗漏会被报告。 |
| E | Scope | 仅Znawca、Ekspert | 目标文件的哪些列参与。见§3.3。 |
| F | Question Type | 仅Znawca、Anvil、Ekspert | 一种或多种类型，以;分隔。空 = 软件随机组合可用类型。权威类型列表在第2行作为设计者备忘，并与每个引擎声明的功能进行验证。 |
| G | Number of Questions | Znawca、Anvil、Ekspert、Sokole Oko | 从题库中抽取多少项目。如果数字超过题库大小，使用所有项目并警告设计者不足。空 = 整个题库。 |
| H | Learning / Testing | 所有评分引擎 | L或T。见§5。 |

为不使用某列的引擎填入的单元格（例如Sokole Oko的Scope）是设计者警告，而非错误；该值被忽略。
3.3 E列 — Scope表示法
两种标记形式，可自由混合，以;分隔：
松散列 — C · 该列加入题库，引擎可将其用作提示或答案。
定向对 — K --> J · K列为提示，J列为答案。方向固定。
可选显式双向 — J <--> K · 两个方向都允许，但仅限于这两列之间。
示例：C; F; K --> J = C和F可自由组合，加上固定的K提示J的问题。[假设—需确认] 如果至少存在一个定向对，松散列仍生成自己的问题；定向对仅约束自身。箭头周围的空格被忽略；->被接受为同义词。
对于Ekspert，其数据是JSON而非表格，同样的表示法指向命名属性而非列字母；映射是Ekspert内部的，此处不涉及。
3.4 第三层文件
已由各引擎定义和拥有。编排器将其视为不透明的，但有三个例外需要通用理解：包/检查点标识列、项目计数，以及（对于Companion）_M / _F文件名约定（§4.3）。

4. 架构
4.1 组件
外壳 — 面向学习者的框架：菜单、课程列表、界面语言选择器、两个进度条、反馈屏幕。外壳而非引擎拥有所有进度显示。
编排器 — 读取编译后的课程脚本，将每行解析为调用包，启动正确的引擎，接收结果，前进。
引擎 ×6 — 现有软件，被嵌入。
内容流水线 — 上传 → 解析 → 验证 → 编译 → 发布。
后台 — 课程状态、验证报告、运行时警告日志、学习者和教师管理。
API + 数据库 + 媒体存储。
4.2 引擎合约
这是集成的核心，必须在构建任何其他内容之前定义。每个引擎被包装以暴露相同的接口：
输入 — 调用包（JSON）：引擎名称、解析的数据文件路径、包/检查点、scope表达式、题型、项目数、模式（L/T）、学习者性别、界面语言、恢复令牌。
输出 — 事件，实时发出：activityReady { itemCount } · itemStarted { index } · itemResolved { index, score 0…1 } · activityFinished { totalScore, perItemDetail[] }。
score作为分数覆盖所有三种评分现实：Znawca/Anvil为0或1；Ekspert返回其部分分数；Sokole Oko返回找到的区域 ÷ 总区域（4个中的3个 = 0.75）。
activityReady { itemCount } 让外壳能够在第一个问题出现之前绘制问题条，包括那些项目数无法从G列获知的引擎。
两种集成策略，在引擎盘点后选择：
（A）嵌入并包装 — 每个引擎在沙盒框架中运行；每个引擎的轻量适配器将合约翻译为引擎已理解的内容，并将其内部事件翻译回来。保留现有可用代码和完成的皮肤。推荐默认方案。
（B）移植 — 针对合约原生重建引擎。仅适用于无法嵌入或无法发出逐项事件的引擎。
现实的风险是某个引擎目前将结果保留在内部并仅在最后报告。最低可接受的改造是逐项事件发出；没有它，问题条无法动画。
4.3 学习者性别和Companion文件解析
性别在注册时声明一次。其唯一功能是Companion引擎的文件选择：C列中的基础名解析为<name>_M.xlsx或<name>_F.xlsx及匹配的媒体子文件夹。
学习者不能自行更改。管理员可以更正真正的注册错误。
如果所需的变体缺失，编排器回退到可用的变体，继续课程，并针对该课程引发阻塞性错误以便修复。学习者不会看到任何异常。
验证器在发布前检查课程中每个Companion调用是否都存在两种变体。

5. 模式、掌握和评分
5.1 学习模式（L）
项目循环直到掌握。首次遇到答对的项目立即掌握。曾经答错的项目需要连续两次答对；任何时刻的失败将该计数器重置为零。未掌握的项目以随机顺序重新抽取，与剩余题库混合。
退出机制。一个可见的退出选项（"我放弃——下一个活动"），在可配置的完整循环次数后可用[假设—需确认：3]。使用它结束活动，记录为放弃，并将未掌握的项目写入学习者的失败项目账本，以便REVIEW检索。
5.2 测试模式（T）
每个活动尝试一次，从逐项分数求和产生百分比。测试不可重考。每个失败或部分失败的项目被写入失败项目账本（学习者、课程、单元、引擎、文件、项目ID、日期、分数）。
5.3 反馈
每次测试活动后：分数加上逐项的错误清单。
单元结束时：整个单元测试活动的总分、逐活动分解和一个水平称号。
水平称号不是硬编码的。每种界面语言有一个纯文本文件，每个分数段一行，例如0-10: Total Noob … 91-100: Straight A Student。添加或编辑分数段是文件编辑，不是代码更改。缺失文件 = 显示分数但不显示称号。
5.4 中断和恢复
课程可以自由中断。返回时，学习者从当前活动的开头重新开始；所有先前完成的活动及其分数保持有效。中断活动中学习模式的掌握进度被丢弃；已完成活动的测试分数永不丢失。中断的测试活动计为尚未尝试，并完整重新提供[假设—需确认]。

6. REVIEW
B列中的REVIEW不是引擎，而是对编排器的指令：从学习者过去的失败中重建一个活动。
C列/D列如果填写，将检索范围缩小到特定文件或包；空 = 当前课程中所有记录的失败。
G列限制检索的项目数。
H列强制为L：复习是为了学习，其结果永远不产生测试分数。
项目在复习中被掌握（连续两次答对）后离开账本。其历史保留用于统计。
如果学习者没有记录的失败，该步骤被静默跳过——这是正常的，不是错误，不会引发警告。

7. 验证和错误报告
学习者永远不应看到技术问题。课程设计者必须能够提前看到每个问题。三个层次：
第1层 — 上传验证（发布前）。上传时，文件被解析和检查，并生成精确到单元格的报告。每个发现都标明课程、单元、文件、行、列和单元格，例如
ERROR — Deutsch_A1 / Unit 4 / U04_lesson.xlsx / row 12, column C: file "Dialog_Bahnhof" not found in unit folder.
WARNING — Deutsch_A1 / Unit 4 / U04_lesson.xlsx / row 17, column D: no checkpoint given for Companion; whole script will play.
WARNING — Deutsch_A1 / Unit 7 / U07_lesson.xlsx / row 5, column G: 30 items requested, 18 available; all 18 will be used.
严重级别：ERROR阻止发布 · WARNING允许发布并记录 · INFO为建议。检查包括：未知引擎名称、缺失数据文件或媒体文件夹、不存在的包或检查点、格式错误的Scope表达式、该引擎未知的题型、项目数不足、缺失_M/_F Companion变体、第一层文件中单元编号断号、空课程脚本。
第2层 — 课程开始前的预解析。课程运行前立即解析每行。无法运行的步骤在活动条绘制前被排除，因此条始终真实，不会在课程中途缩小。
第3层 — 运行时警告日志。如果某步在播放过程中仍然失败，编排器跳过它并继续，将完整诊断记录到管理面板。学习者看到的是不受干扰的课程。
报告在后台可用，并可选在上传时通过邮件摘要发送。

8. 进度显示
两个进度条，始终可见在屏幕最顶部，由外壳拥有。
Activities   -----  -----  -----  -----  -----  -----  -----
Questions    -- -- -- -- -- -- -- -- -- -- -- -- -- -- -- --
活动条：课程脚本每个可执行行一个段。
问题条：当前活动中每个项目一个段。来源：G列，或G为空时的解析题库大小；对于Direct，每个脚本步骤一个段；对于Companion，从一个语音输入到下一个语音输入之间的每个段落一个段。
状态和颜色（取自已建立的调色板）：
| 状态 | 外观 |
| 尚未到达 | 深金棕绿色 |
| 当前 | 亮绿色，段放大并轻微发光 |
| 已完成/答对 | 金黄色 |
| 答错（Znawca、Anvil、Ekspert、Sokole Oko） | 不祥的红色 |

学习模式行为：进度条不会随每次循环增长。失败的项目保持红色原地；重新出现并最终掌握时变为金黄色。红色项目的回收是随机的。当没有红色段剩余或使用退出机制时，活动完成。
部分分数（Ekspert、Sokole Oko）[假设—需确认] 渲染为部分填充的段：金色到所获分数比例，红色超出部分。

9. 账户、访问、商业
注册：电子邮件、密码、声明的性别、界面语言。
界面语言独立于课程语言。课程以其固定的语言教学，不受UI设置影响。UI字符串存储在按语言的资源文件中，水平称号文件也是如此。
访问控制：课程需要有效的付费权限；课程内适用单元锁定。
支付：[开发者决定] — 模型（单一订阅/按课程/试用）和提供商均待商定。具有强大定期计费支持且覆盖波兰本地支付方式的提供商是实际的出发点。
未成年人。许多学习者未满16岁；访问由父母或监护人安排和付费，即构成同意。开发者应记录同意证据（谁付费、何时、为哪个学习者），收集最少必要数据，并保持学习者记录可应要求删除。
教师/观察者角色
只读账户，通过学习者或监护人发放并可撤销的邀请码与学习者关联。观察者可以看到：最后活动日期、任务时间、已完成单元、测试分数和趋势。观察者看不到学习者显示名以外的任何个人数据，且不能更改任何内容。

10. 需存储的数据
用户（含声明性别、界面语言、权限）· 课程和单元，含发布状态和编译脚本缓存 · 注册和单元解锁状态 · 活动结果（模式、分数、时间戳、放弃标志）· 逐项结果 · 失败项目账本 · 恢复检查点 · 每次上传的验证报告 · 运行时警告日志 · 观察者链接。
原始.xlsx文件是创作的唯一真相来源，但运行时读取在发布时生成的编译缓存。上传文件永远不会改变当前正在体验课程的学习者所见；更改在下次课程开始时生效。
