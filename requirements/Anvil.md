
Project Proposal: "Anvil" — Interactive Learning & Testing Platform
1. Project Overview
Anvil is an educational software platform designed to teach and test knowledge across any discipline, with an initial focus on the natural sciences. It operates on a simple but powerful principle: course authors create content using standard Excel files and organize supporting media (images, audio, video) in folders, with no specialized authoring tool required. The software reads these files and presents interactive exercises to the learner in a variety of formats — multiple choice, fill-in-the-blank, matching, matrix-style questioning, and more — all auto-detected from the structure of the spreadsheet.
The platform exists in two forms: a local Windows desktop application for private, offline use, and a public-facing website with user registration, authentication, and payment. Both versions share the same core functionality.
2. Platform & Deployment
The desktop version is a standalone Windows application intended for a single user (the project owner) working offline. It should be able to read course files from a local directory without requiring an internet connection.
The web version is a browser-based application hosted on a server. It serves a modest user base — anticipated to be in the range of dozens to a few hundred concurrent users at most. Learners access the site through a standard web browser, create an account, authenticate, and pay for access (payment model and provider to be discussed separately between the project owner and the developer). Only the project owner uploads, removes, or replaces courses; there is no multi-instructor or user-generated content model.
Whether the two versions share a common codebase (for example, a web-based core wrapped in a desktop shell such as Electron for the offline version) or are developed as separate applications is left to the developer's judgment, though the project owner should be advised that a shared codebase significantly reduces long-term maintenance burden.
A key question that remains open and should be discussed early is whether the web version must be fully responsive for mobile phones and tablets, or whether a desktop/laptop browser experience is sufficient. This has a meaningful impact on interface design, particularly for question types involving matrices, matching, and multi-image layouts.
3. Course Data Architecture
Each course is represented by a single Excel file (.xlsx). The name of the file is the name of the course. A subfolder in the same directory shares the course's name and contains all associated media files: images (.jpg, .png), audio (.mp3, .wav), and video (.mp4, and potentially .avi or .webm — the developer should confirm which video formats are practical for browser playback, as .avi is problematic in web contexts).
For example, a course called "European Songbirds" would consist of a file named European Songbirds.xlsx and a folder named European Songbirds/ containing all referenced image, audio, and video files.
In addition to media files used as question content, the subfolder may contain optional audio narration files for individual cells. These are named using the pattern [Column][Row].mp3 — for example, C183.mp3 corresponds to the content of cell C183 in the Excel file. When such a file exists, a small loudspeaker icon appears next to the corresponding text element on screen, allowing the learner to hear the content read aloud. When the file does not exist, no icon is shown and no fallback (such as text-to-speech) is used. The course functions perfectly well with no narration files at all; this feature is entirely optional and can be used selectively.
4. Question Types
The software supports nine distinct question types. Crucially, the course author does not manually specify which type a given row belongs to. Instead, the software auto-detects the question type based on the content and structure of each row in the Excel file. The detection logic is described below alongside each type.
Type 1 — Media Identification with Multiple Choice
Column A contains a media filename (image, audio, or video). Column B is empty. Column C contains the correct text answer. Columns D, E, F (and optionally G) contain incorrect text answers, providing a total of three to five answer choices.
If Column A references an image file, the image is displayed. If it references an audio file, the audio is played once. If it references a video file, the video is played. The learner selects the correct answer from among the randomized choices presented as buttons.
Detection rule: Column A ends with a recognized media file extension, Column B is empty, and Columns C onward contain plain text (not filenames).
Type 2 — Matrix / Multi-Sub-Question with Shared Media
This type presents a single piece of media alongside multiple sub-questions, each answered by selecting from a shared set of options. It is constructed across multiple consecutive rows in the Excel file.
The first row of the group behaves like a header: Column A contains the media filename, and Columns C, D, E (and potentially more) contain the option labels that will serve as column headers in the matrix — for example, "Aggressive," "Scared," "Female," or simply "True," "False," or "Yes," "No," "Unknown."
Each subsequent row that has a blank Column A is treated as a sub-question belonging to this group. Column B of each such row contains the sub-question text. The grouping continues until a row with content in Column A is encountered, which marks the beginning of a new, separate question.
Column C of each sub-question row contains the text of the correct option (which must exactly match one of the option labels defined in the header row). 
Type 3 — Media with Explicit Question and Multiple Choice
This is identical to Type 1, except that Column B contains a specific question to display above the answer choices. The learner sees (or hears, or watches) the media from Column A, reads the question from Column B, and selects from the randomized answer options in Columns C onward (Column C being correct).
Detection rule: Column A ends with a recognized media file extension, and Column B contains text.
This type also supports a multi-sub-question variant: if subsequent rows share the same media (Column A blank, sub-questions in Column B, answers in C/D/E), they are grouped together and presented sequentially on the same slide with the same media displayed, following the same grouping logic as Type 2.
Type 4 — Cloze (Fill-in-the-Blank with Selection)
Column A contains a passage of text with embedded blanks. Each blank is denoted by square brackets containing a semicolon-separated list of options. The first option in each bracket is always the correct answer; the software randomizes the order when presenting them to the learner. For example:
The bald eagle is a [large; small; timid] species of [American; Kenyan; Asian] bird.
Each bracketed section becomes an inline dropdown or button group from which the learner selects an answer.
Detection rule: Column A contains text (not a filename, not an asterisk) that includes at least one instance of [...] with semicolons, and the brackets do not begin with a tilde (~).
Type 5 — Cloze (Fill-in-the-Blank with Typing)
This functions identically to Type 4, except that blanks marked with a tilde (~) at the start require the learner to type the answer rather than select it. The options listed after the tilde are used for validation (the first being correct) and, depending on the feedback mode, may be shown as hints or corrections.
A single passage may mix selection-based and typing-based blanks:
The bald eagle is a [large; small; timid] species of [~American; Kenyan; Asian] bird.
Here the first blank is multiple-choice; the second requires typing.
Detection rule: same as Type 4, but the presence of ~ inside any bracket triggers the typed-answer mechanic for that specific blank.
Type 6 — Matching Exercise
Column A contains an asterisk (*) to signal that this is not a continuation of a previous question. Columns C through however many are needed each contain text segments separated by asterisks. For example:
Column C: Bird A lays eggs that * are blue
Column D: As Bird B matures, its feathers * become red
Each asterisk splits the cell content into parts. All first-parts form one column on screen, all second-parts form another, and (if a second asterisk is present) all third-parts form a third column. The columns are independently scrambled, and the learner must reassemble the correct pairings (or triplets).
Detection rule: Column A is exactly *, and the content in Columns C onward contains * as internal separators but does not end with a recognized media file extension.
Type 7 — Text Question with Image Answer Choices
Column A contains a text question (not a filename). Columns C, D, E, F (and potentially more) contain image filenames. Column C is the correct image. The software displays the question and shows the images in randomized positions; the learner clicks the correct one.
Detection rule: Column A contains text that does not include brackets or an asterisk, and the values in Columns C onward end with recognized image file extensions.
Type 8 — Persistent Image (or Audio) Set with Sequential Questions
Column A contains an asterisk (*). Columns C, D, E, F (and so on) each contain a text label and a media filename separated by an asterisk — for example: Eagle * eagle.jpg or Stork song * stork_call.mp3.
The software displays (or makes playable) all media items simultaneously on screen, with their labels hidden. It then presents the labels one by one as questions (in randomized order), and the learner must click the corresponding image (or audio play button) for each. The media items are reshuffled in position after each answer to prevent positional memorization.
Detection rule: Column A is exactly *, and the content in Columns C onward contains * as an internal separator where the portion after the asterisk ends with a recognized media file extension. This is how the software distinguishes Type 8 from Type 6: the presence of media filenames after the asterisk.
Type 9 — Audio Stimulus with Question and Image Choices
Column A contains an audio (or video) filename. Column B contains a question. Columns C, D, E contain image filenames (Column C being the correct answer).
The audio is played (or video shown), the question is displayed, and the learner selects from among the displayed images.
Detection rule: Column A ends with a recognized audio/video extension, Column B contains text, and Columns C onward end with recognized image file extensions.
Detection Priority and Ambiguity
Because question types are auto-detected, the software must apply the detection rules in a specific priority order to avoid misclassification. The developer should implement a clear decision tree and document it. In cases of genuine ambiguity (a row that could plausibly be interpreted as more than one type), the software should flag the row during validation (see Section 9) so the course author can adjust the Excel file.
5. Session Modes and Settings
Before beginning a session, the learner configures the following options.
Mode selection: The learner chooses between Learning Mode and Testing Mode. In Learning Mode, any question answered incorrectly is re-queued and will reappear at a random point later in the session; the session continues until all questions have been answered correctly at least once. In Testing Mode, each question appears exactly once regardless of whether the answer is correct or incorrect, and a final score (number and percentage correct) is displayed at the end.
Scope: The learner specifies how many questions to include in the session. The upper limit is the total number of questions available in the selected course file. The selection of questions from the pool should be randomized unless the learner is working with recycled questions (see Section 8).
Question format filter: The learner may choose to restrict the session to a single question format (for example, only multiple choice, or only cloze exercises) or to allow a mixture of all formats present in the course file.
Timer: The learner may optionally set a time limit for the session — for example, 15, 20, 30, or 60 minutes. When the timer expires in Testing Mode, unanswered questions are marked as incorrect and the final score is calculated. 
Feedback mode: The learner selects one of two feedback behaviors for incorrect answers. The first option, "Let me try again," re-queues the question without revealing the correct answer. The second option, "Show me the correct answer," immediately displays the correct answer (and, for cloze and matching exercises, highlights which specific parts were wrong) before moving to the next question. In Testing Mode, the second option is always in effect since questions do not repeat.
6. User Interface and Localization
The interface should be clean, uncluttered, and focused on the learning content. The design specifics are left to the developer, but a few requirements are firm.
Interface language: A small button (ideally styled with national flags or a globe icon) allows the user to switch the interface language between English, Polish, Russian, Mandarin Chinese, and Arabic. This affects all menus, buttons, labels, instructions, and system messages. The project owner will provide all interface translations.
Content language: Course content is displayed exactly as written in the Excel file and is independent of the interface language. A course written in Polish will display in Polish regardless of the interface language setting.
Right-to-left support: When Arabic is selected as the interface language, the entire layout must mirror to conform to right-to-left reading conventions. This includes navigation elements, text alignment, button order, and progress indicators. This is not optional and must not be reduced to merely translating labels while keeping a left-to-right layout.
Loudspeaker icons: As described in Section 3, any text element on screen (question text, answer option, cloze passage segment) should display a small speaker icon if a corresponding audio file exists in the course subfolder. Clicking the icon plays the audio. If no file exists, no icon appears.
7. User Accounts, Authentication, and Payment
The web version requires user registration with a username and password. Each person creates one account, which stores their identity and performance history. Standard practices apply: password hashing, secure sessions, and the ability to reset a forgotten password via email.
A payment mechanism is required to gate access to courses on the web version. The specific payment model (per-course purchase, subscription, tiered access) and the payment provider (Stripe, PayPal, or others) are to be discussed and decided in a separate meeting between the project owner and the developer. The proposal should include this component as a line item in the estimate, with the understanding that the scope will be refined after that discussion.
The desktop version does not require authentication or payment. It operates as a single-user application.
The project owner is the sole administrator. An admin interface (which can be simple) must allow uploading new course files and their media folders, removing courses, and replacing/updating existing courses. No other users have authoring or administrative privileges.
8. Performance Tracking and Question Recycling
The software maintains a per-user performance history for each course. Every question answered incorrectly is flagged and stored. These flagged questions form a "recycling pool" that can be offered to the learner as a dedicated practice option — for example, a "Review difficult questions" button alongside the normal course selection.
A question is removed from the recycling pool only after the learner has answered it correctly three consecutive times across sessions. This means a single correct answer is not enough; the learner must demonstrate retention over multiple encounters.
The storage mechanism for this data (local file, lightweight database, server-side database for the web version) is left to the developer's judgment and technical recommendation.
9. Validation and Error Handling
When a course file is loaded, the software performs a validation pass and reports any issues to the user. Validation checks should include, at minimum: referenced media files that do not exist in the course subfolder, rows whose structure does not match any recognized question type, cloze brackets with fewer than two options, and any other structural inconsistency the developer identifies during implementation.
Error messages must be cell-specific — for example, "Cell A47 references 'robin.jpg,' but this file was not found in the course folder" — rather than merely citing a row number.
Critically, validation errors must not prevent the course from loading. The software should skip or gracefully degrade questions that cannot be rendered (for instance, by omitting a question whose image is missing) and allow the rest of the course to function normally. The learner should be informed that some questions were excluded due to data issues.
10. Points for Discussion
The following items remain open and should be resolved between the project owner and the developer before or during the early stages of development.
The first is the payment model and provider for the web version, as discussed in Section 7. The second is mobile responsiveness: whether the web version must work well on phone screens or only on desktop and laptop browsers. The fourth is the technology stack for both the desktop and web versions, which the developer should recommend based on their expertise and the requirements described here. The fifth is the supported video formats, particularly for the web version, where browser compatibility may limit options.
11. Summary of Deliverables
The project consists of two deliverables: a Windows desktop application for offline, single-user use, and a web application with user accounts, payment, and admin course management. Both share identical core functionality — reading Excel-based course files, auto-detecting nine question types, presenting interactive exercises with randomized answer placement, supporting learning and testing modes with configurable scope, timer, and feedback settings, tracking per-user performance with a spaced recycling system, and offering a fully localized interface in five languages including right-to-left Arabic.
