## 三份合约

### 1. 内容编译合约

引擎声明以下能力，输入源文件（第三层私有数据）、输出**不可变 Course Version**（ADR-0004）：

| 能力 | 输入 → 输出 |
|---|---|
| `capabilities` | → 引擎能力声明（题型清单、适用第二层列、媒体白名单） |
| `parse` | 源文件 → 中间结构 |
| `validate` | 中间结构 → `[E_PUBLISH 错误 | WARNING | INFO]`，每条带 `course/unit/file/row/col/cell` |
| `compile` | 中间结构 → CourseVersion（活动/题目/概念/素材稳定 ID + 资产清单） |
| `estimateItemCount` | → int（随机引擎可提前确定，供进度条） |
| `migrate` | (fromVer, toVer, payload) → payload |

第三层 schema 与解析器由**各引擎维护**；平台只拥有统一编译信封与流水线调度；运行时一律消费编译产物。

### 2. 运行时合约

**输入「调用包 JSON」**（每字段定类型与必填）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schemaVersion` | string | 是 | 合约版本，启动时协商 |
| `engine` | enum | 是 | znawca / anvil / ekspert / sokole-oko / companion |
| `courseVersionId` / `activityId` / `attemptId` | string | 是 | 稳定 ID |
| `randomSeed` | int | 是 | 编排器下发，可追溯 |
| `mode` | enum | 是 | L / T |
| `learnerSex` | enum\|null | 否 | M / F，仅 Companion 用 |
| `interfaceLang` | string | 是 | 平台统一语言清单（暂 BCP-47） |
| `scope` | string\|null | 否 | 仅 Znawca / Ekspert |
| `questionTypes` | string[]\|null | 否 | 仅 Znawca / Anvil / Ekspert |
| `package` / `checkpoint` | string\|int\|null | 否 | D 列 |
| `itemCount` | int\|null | 否 | G 列；null = 整池 |
| `resumeToken` | string\|null | 否 | 恢复点透传 |
| `items[]` | array | 是 | 编译产物题目引用（itemId + payloadRef） |

**输出事件**（四事件为主里程碑），统一头 `eventId(uuid) · seq(int) · ts(epoch ms)` 支持幂等重放：

| 事件 | payload |
|---|---|
| `activityReady` | `{ itemCount }` |
| `itemStarted` | `{ index }` |
| `itemResolved` | `{ index, score(0–1), dimensions[], attemptNumber, encounterNumber, elapsedMs, errorType?, masteryEvidence? }` |
| `activityFinished` | `{ totalScore(0–1), perItemDetail[] }` |

**状态机（活动生命周期）**：

```
activityReady → itemStarted → (itemResolved)* → activityFinished
   任意点 → paused → resumed（从 activity 起点）
   任意点 → cancelled（退出确认）
```

**统一错误码**：

| 码 | 语义 | 行为 |
|---|---|---|
| `E_PUBLISH` | 发布阻断（校验失败） | 课程不可发布 |
| `E_TECH` | 活动技术失败 | 跳过 + 诊断日志，学习者无感 |
| `E_GRACE` | 学习者可见降级（媒体缺失等） | 展示降级提示 |
| `E_SKIP` | 显式跳过（学习逃逸） | 记跳过，继续 |

### 3. UI 宿主合约

- `mount(container, themeTokens) / unmount()`
- 统一：主题、尺寸、焦点、键盘、RTL、媒体权限、暂停、退出确认、错误界面
- 恢复点协议：`resumeToken` 透传

## 评分约定

- 归一化总分 `score 0–1` 保留，同时附带：
  - `dimensions[]`：Ekspert 各轴 / Sokole 各区域 / Companion 音素·节奏·语调（子结构由各引擎第三层 schema 定义，待补）
  - `attemptNumber` 与 `encounterNumber`
  - `masteryEvidence`：由平台策略决定是否掌握
  - `feedbackRef`、提示使用、作答耗时、错误类型
- 引擎只提交领域评分证据，判分裁决由平台统一求值管线（ADR-0005）。
- 借鉴 LTI（平台—工具边界）与 xAPI（学习事件）；MVP 不完整实现 LTI/LRS。

## 红线（不可违反）

- 判分裁决、持久学习状态、自适应策略、权威进度**在后端**
- 呈现状态、即时交互、媒体控制、可重建的临时状态**可在客户端**
- 评分/进度/错题/调度规则全放后端，前端只展示 + 调用
