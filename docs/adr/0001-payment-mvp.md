# ADR-0001: 支付功能 MVP 阶段策略

- 状态：已接受
- 日期：2026-08-25
- 决策人：恺欣

## 背景

OPEN-QUESTIONS #6 提出支付模型与提供商待定。项目处于验证阶段，暂无真实收费的急迫需求；但支付牵涉课程访问门控与后端接口，若完全不设计，后续接入会大量返工。

## 决策

MVP 阶段**不实现真实支付**；但（1）做出支付页面（UI），（2）后端预留支付接口（留好口子），（3）先把触发支付的业务链路设计定死。

## 理由

验证阶段无收费急迫需求，真实支付（循环扣费、波兰本地支付、资质合规）成本高且非当前主线；先留接口 + 定链路，可避免后续返工，又不阻塞切片。

## 影响面

- 平台腿后端：预留 payment 接口占位（不接真实网关）。
- 外壳：商城/课程购买入口 → 购买页跳转的交互链路。
- `docs/OPEN-QUESTIONS.md` #6 状态更新为「已定（MVP 策略）」。

## 后果

- 利：接口与链路前置，接入真实支付时改动最小。
- 弊：购买页 UI 暂时是「空壳」，需在验收口径中明确「MVP 不校验真实扣款」。
- 回看点：接入真实支付时需回看此 ADR，补选提供商（需覆盖波兰本地支付）。
