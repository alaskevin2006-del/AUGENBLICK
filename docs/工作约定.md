# 工作约定

> 每个新项目开工前，先读本文件 + `docs/合约.md` + `docs/边界与验收.md` 及相关 ADR，再动手。
> 本文件是「怎么协作」的唯一约定，与「做什么」（进度）分离。

## 一、项目结构（单仓库 monorepo）

- 根目录 `AUGENBLICK/` = **一个 git 仓库**，所有子项目共享同一份历史。
- 顶层三区（与 `README.md` 一致）：
  - `requirements/` —— 需求文档；英文 `.md` 是 agent 唯一正文入口，`sources/` 归档原版+中文，`feedback/` 反馈
  - `docs/` —— 工程治理（进度/合约/边界验收/ADR/工作约定）
  - `src/` —— 开发产物（代码，未来；每个引擎在此各建子目录）
- 共享文件在根目录 `docs/`（**全局契约，唯一**）：
  - `docs/进度.md` —— 全局进度仪表盘（单一事实源）
  - `docs/baseline/` —— 产品基线（平台 + 5 引擎 + Direct 保留位权威基线，各子项目开工必读）
  - `docs/合约.md` —— 引擎统一合约（带版本，唯一）
  - `docs/边界与验收.md` —— 全局形态边界 + 各引擎 docs 索引
  - `docs/ARCHITECTURE.md` —— 架构地图
  - `docs/GLOSSARY.md` —— 术语表
  - `docs/OPEN-QUESTIONS.md` —— 待决问题清单
  - `docs/adr/` —— 架构决策记录
  - `docs/工作约定.md` —— 本文件

## 治理文件分层

- **全局契约（只放根 `docs/`，唯一，各引擎不复制）**：合约、架构、术语表、工作约定、全局进度仪表盘、跨引擎 ADR。
- **引擎特有（放 `src/<引擎>/docs/`，各引擎各自维护）**：本引擎边界、本引擎验收、本引擎详细进度、引擎内部 ADR。
- 根 `docs/边界与验收.md` 只保留全局形态边界 + 指向各引擎 docs 的索引，详细边界下沉到各引擎。

## 二、项目 / 对话框分工

| 项目 | 职责 | 何时开 |
|---|---|---|
| **规划总控**（根目录） | 决策 / 流程 / 审文档 / 维护 docs | 现在，贯穿全程 |
| **平台开发** | 外壳+编排器+后端+内容流水线的代码 | 步骤③ |
| **引擎 × 5 + Direct 保留位**（`src/<引擎>/`） | 各引擎迁移/开发 | 按排期逐个开 |
| **部署运维** | 服务器 / 域名 / 上线 | 支线需要时 |
| **安全合规** | 合规评估 | 支线需要时 |

- 每个引擎（或平台）在 `src/` 下各自目录**单开一个项目运行**，上下文隔离。
- 引擎项目开序：Znawca 最先（切片）；Anvil/Ekspert/Sokole Oko/Companion 等合约冻结后开；Direct 只做「澄清需求」；语音评估可并入 Companion。

## 三、交接规则（三条铁律）

1. **靠文件 + git 交接，不靠记忆/口头**：各项目 workspace 记忆相互隔离，`docs/` 是唯一可靠交接点；「我在别的项目说过」无效，写进文件才算数。
2. **开工先读共享文件**：每个项目开工前读 `docs/baseline/<本引擎>.md` + `docs/baseline/README.md` + `docs/合约.md` + `docs/边界与验收.md` + `docs/ARCHITECTURE.md` + `docs/GLOSSARY.md` + 相关 ADR，再动手。
3. **决策回流总控**：任何跨引擎决策，写成 ADR 进 `docs/adr/` 或回报总控定夺，不让决策滞留在单个项目里。

## 进度同步机制

- **引擎项目 AI 只写自己的 `src/<引擎>/进度.md`**（详细日志），绝不跨目录碰根文件。
- **根 `docs/进度.md` 仪表盘由规划总控维护**，每个引擎只占一行（状态/阻塞项/下一步）。
- 同步靠一个动作：**引擎项目状态变化时回报一句「X 引擎：状态 A→B，阻塞 C」给总控，总控更新仪表盘那一行**。单向同步，不自动、不双向。

## 四、开发流程（两条腿 + 主线 + 支线）

**两条腿**：
- 平台腿（全新从零）：外壳 + 编排器 + Web 后端（API/DB/认证/支付）+ 内容流水线 + 后台。
- 引擎腿（5 引擎 + Direct 保留位）：Znawca 复用内核（core + 答题 UI，剥离 Electron 壳）；其余按复用度新写；Direct 待澄清。

**主线七步**：

| 步骤 | 内容 |
|---|---|
| 1 | 审阅文档，钉死边界 + 验收标准 |
| 2 | 定技术方案 + 开发顺序 |
| 3 | 建项目骨架（含平台骨架） |
| 4 | 定义引擎统一合约（三份，带版本） |
| 5 | Znawca 切片 = 平台最小骨架 × Znawca 引擎接合，跑通一节课 |
| 6 | 平台逐步完善 + 其余引擎并行接入（随接随集成） |
| 7 | 测试与验收（贯穿全程） |

**支线三条（全程并行）**：服务器+域名 / 安全合规 / 语音评估调优。

## 五、三条架构红线

1. **逻辑全走 API，不进浏览器**（评分/进度/错题/调度全在后端）。
2. **合约冻结前，4 引擎只并行准备合约无关内容**；冻结后再写适配器接入。
3. **V1 = 纯在线 Web，不做 PWA**；离线后置走原生 App。

## 六、引擎目录模板

新建引擎时复制 `src/_template/`，改名为 `src/<引擎>/`，结构：

- `README.md` —— 引擎说明 + 依赖合约版本
- `docs/边界.md`、`docs/验收.md` —— 本引擎边界与验收
- `进度.md` —— 本引擎详细进度（append-only）
- `src/`（core / ui / adapter / datasource）、`tests/`（contract 合约一致性测试）

目录名用无空格小写：`znawca` / `anvil` / `ekspert` / `sokole-oko` / `companion` / `direct` / `platform`。

## 七、记忆规则

- 各项目 workspace 记忆隔离，只记自己的细节日志。
- **全局进度必须汇总到 `docs/进度.md` 这一份**，禁止散落在各项目 workspace 记忆里。
- 个人跨项目偏好写 `~/.workbuddy/MEMORY.md`，不写项目决策。
