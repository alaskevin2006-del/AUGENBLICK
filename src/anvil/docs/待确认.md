# Anvil 待确认问题清单

> Anvil 引擎特有的未决事项。每项含「问题描述 + 参考做法 + 状态」。解决后：引擎内部决策写 `docs/adr/`；跨引擎 / 需客户拍板回报规划总控，进根 `docs/OPEN-QUESTIONS.md`。
>
> 状态取值（已收敛）：
> - `已定` —— 治理文档 / 平台文档已明确，按此实现即可，无需再确认。
> - `待定·平台` —— 需 AUGENBLICK 平台统一规定（跨引擎，回报规划总控）。
> - `待定·内部 ADR` —— Anvil 内部设计决策，写本引擎 `docs/adr/` 定稿。
> - `待定·实现期` —— 写代码时的实现细节。
> - `待定·全局` —— 归全局 OPEN-QUESTIONS，非 Anvil 独有。
>
> 依据：`docs/` 治理文档（合约 v0.3 / ARCHITECTURE / ADR-0002~0009 / 边界与验收 / GLOSSARY / OPEN-QUESTIONS / 工作约定）+ `requirements/AUGENBLICK.md` + `AUGENBLICK补充说明.docx` + `Anvil补充说明.docx` + `Anvil.md`。

## 一、职责范围

### A1. 账户 / 认证 / 支付 / 后台？
- **问题**：原 `Anvil.md §7` 要求 Web 版注册 + 认证 + 支付 + 课程后台。
- **参考做法**：不归 Anvil。ARCHITECTURE「五方状态归属」+ ADR-0002 明确账户 / 支付归平台；`AUGENBLICK.md §9` 为平台范围。`Anvil.md §7` 是平台化前过时内容。
- **状态**：已定

### A2. 进度跟踪 / 错题回收池？
- **问题**：原 `Anvil.md §8` 要求「连续 3 次答对才移出错题池」。
- **参考做法**：进度 / 错题 / 间隔复习全归 Learning State（五方状态归属），Anvil 不自建。`Anvil.md §8` 是过时内容；「3 次 vs 2 次」是平台内部口径，与 Anvil 无关。
- **状态**：已定

### A3. 随机引擎 vs 渐进 / 顺序播放？
- **问题**：`Anvil补充说明.docx ②` 的「从易到难自然递进」看似与「随机抽题」冲突。
- **参考做法**：平台定 Anvil 为**随机引擎**（GLOSSARY + `AUGENBLICK.md §3.2`），抽取顺序归编排器。难度列仅作**题目属性**进编译产物，Anvil 不做递进 / 顺序排序。
- **状态**：已定

### A4. session 设置（Timer / 反馈模式）归谁？
- **问题**：原 `Anvil.md §5` 的 Timer 与 Feedback mode。
- **参考做法**：mode(L/T)/题量/格式过滤已由第二层 H/G/F 列接管（`AUGENBLICK.md §3.2`）；「再试一次 / 显示答案」被平台 L/T 模式 + 统一反馈吸收。Timer 平台无需求，V1 不实现（`Anvil.md §5` 过时内容）。
- **状态**：已定

## 二、输入输出约定

### B1. 第三层（引擎数据）Excel 格式谁定？
- **问题**：`Anvil.md §3-4` 的列布局 vs `Anvil补充说明.docx ②` 的「难度列 + 首行表头 + 从第 2 行读」；Excel 格式该由谁统一。
- **参考做法**：**Excel 通用格式约定由 AUGENBLICK 平台统一规定**（首行表头、从第 2 行读、难度列、题型列、内容单元媒体判定等通用要素，跨引擎一致，回报规划总控 / 进平台级文档）；Anvil 只自定**题型级列语义**（9 题型槽位、cloze 括号语法、matching 分隔符等），写本引擎内部 ADR。
- **状态**：待定·平台（通用格式约定）+ 待定·内部 ADR（题型级列语义）

### B2. 题型：自动检测 vs 显式题型列？
- **问题**：`Anvil.md` 的「9 题型全自动检测」 vs 平台第二层 F 列显式题型。
- **参考做法**：显式题型（第二层 F 列 + 引擎 `capabilities` 声明 9 题型）；旧自动检测逻辑仅作导入迁移的兼容通道（`migrate`，ADR-0004 回看点）。
- **状态**：已定

### B3. 「内容可为任意媒体」如何落地？
- **问题**：`Anvil补充说明.docx ①` 要求任意题型内容都可是文本 / 图片 / 音频 / 视频。
- **参考做法**：有效（优先级 ③）。重构「内容单元 = 文本 | 媒体引用」的判定与题型分型规则，由本引擎内部 ADR 定稿。
- **状态**：待定·内部 ADR

### B4. 评分口径：0/1 还是部分分？
- **问题**：cloze 多空、matching 多项、矩阵多子题天然有「部分对」。
- **参考做法**：`AUGENBLICK.md §4.2` 已定「Znawca/Anvil 是 0 或 1」——**Anvil 评分 = 0/1，不做部分分**。「一题」的粒度（cloze 每空 vs 整段、矩阵每子题）属 item 划分，由本引擎内部 ADR 定。
- **状态**：已定（item 粒度待内部 ADR）

### B5. 合约能力声明与调用包 / 事件字段？
- **问题**：Anvil 声明哪些能力、消费哪些字段、适用第二层哪些列。
- **参考做法**：`docs/合约.md` 声明 `capabilities/parse/validate/compile/estimateItemCount/migrate`；运行时输入调用包 JSON、输出四事件。**Anvil 第二层适用列 = B/C/D/F/G/H，不适用 E(Scope)**。随机引擎 `estimateItemCount` 可提前确定，利于 `activityReady{itemCount}` 画进度条。
- **状态**：已定（itemCount 确定性实现期确认）

## 三、与其他引擎 / 平台的接口依赖

### C1. 上游喂什么、下游消费什么？
- **参考做法**：内容流水线（编译产物）→ 编排器（调用包）→ Anvil（Activity Host 内）→ 事件 → Learning State / 统一求值管线。不直读 Excel（ADR-0004/0008），媒体走签名 URL。
- **状态**：已定

### C2. 与 Znawca 的复用边界？
- **问题**：进度.md 标复用度 ~50%，具体复用什么。
- **参考做法**：**Znawca 代码是可选参考、非强制**。可照搬选择/图片/填空题型 UI + 会话框架；矩阵/匹配/音频/多图题型 + 题型分型逻辑为新增。是否复用按实现需要决定，不必先定「复用/新写」清单。
- **状态**：已定（按需复用）

### C3. 是否参与 `_M/_F` 性别文件约定？
- **参考做法**：不影响。`_M/_F` 是 Companion 专属；Anvil 只用 D(package)/F(题型)/G(题数)/H(L-T) 列。
- **状态**：已定

### C4. 双品牌 Polyglot / Savant 下 Anvil 有差异吗？
- **参考做法**：无差异（ADR-0006：引擎与格式完全相同，品牌走运行时配置）。
- **状态**：已定
