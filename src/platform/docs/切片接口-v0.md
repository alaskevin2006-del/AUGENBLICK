# Znawca 切片接口 v0（前后端共享契约）

> 目的：Znawca 垂直切片的前后端唯一接口约定。对齐根 `docs/合约.md` v0.3，只取切片必需子集。
> 本文件是切片内部工作文档，不改全局合约；切片跑通后经验回流根合约。

## 一、技术形态

- 后端：Django 5.2 + DRF，**开发期 SQLite**（生产切 PostgreSQL 17，仅改 settings，见 ADR-0006；此偏离记录于平台 ADR）。
- 前端：Vite + React 18 + TS，dev server 代理 `/api` 与 `/media` 到 `http://localhost:8000`。
- 端口：后端 8000，前端 5173。
- 认证：~~切片期**无认证**~~（v0.1 增补：Token 认证，见 §八）。
- Celery/Redis/对象存储：切片期不做；课程导入用 management command 同步执行，媒体走 Django 开发服务器 `/media/`。

## 二、编译产物（CourseVersion payload，Znawca 第三层）

后端导入 Znawca V2 课程目录（xlsx + `media/` + `speech/` + 正误音效）后，存为不可变版本，payload 结构：

```jsonc
{
  "schemaVersion": "0.3",
  "engine": "znawca",
  "courseVersionId": "birdsv2_eng@<content-hash-8>",
  "title": "Birds of Europe (V2 sample)",   // xlsx A1
  "languageCode": "Eng",                     // 文件名 _Eng 后缀
  "formatVersion": "v2",
  "columns": [
    {
      "index": 2,                            // Excel 列号（1 起）
      "title": "Name / Bird",                // 原始表头
      "filterOnly": false,                   // "#" 前缀
      "role": "both",                        // both | question-only("$") | answer-only("*")
      "forward": "Name",                     // "/" 前段（题干）
      "reverse": "Bird"                      // "/" 后段
    }
  ],
  "items": [
    {
      "id": "black-headed-gull",             // normalizeKey(name)：小写、空白→连字符、去标点
      "name": "Black-headed Gull",
      "sourceRow": 2,
      "values": { "Scientific name / Species": ["Chroicocephalus ridibundus"] },
      "media": [ { "kind": "image", "url": "/media/<cid>/black-headed-gull-photo.jpg" } ],
      "cellMedia": { "Song / Recording": [ { "kind": "audio", "url": "/media/<cid>/black-headed-gull-song.wav" } ] }
    }
  ],
  "speech": [ { "coord": "B2", "url": "/media/<cid>/speech/Eng/B2.wav" } ],
  "feedbackSounds": { "correct": ["<url>"], "incorrect": ["<url>"] }
}
```

规则：
- 表头解析与桌面版 `parseColumnTitle` 一致：`#`/`$`/`*` 前缀 + `正向 / 反向` 双题干（V2 两侧必填，缺则导入报错）。
- 单元格文本多值用 `;` 拆分；`/` 是媒体文件名多变体分隔（沿用桌面语义，编译期不展开别名，运行时评分逻辑沿用桌面 `evaluateAnswer`）。
- 单元格媒体：纯文件名（不含路径），编译期在课程目录 `media/` 解析为 URL；缺失 → warning，不阻断。
- A 列（V2）＝整行主媒体引用，进 `media[]`；B 列＝名称；C 列起＝属性。
- `normalizeKey` 与桌面版一致：trim → 小写 → 空白串转 `-` → 去掉非字母数字连字符。

## 三、REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/courses/` | 课程版本列表：`[{courseVersionId, title, languageCode, engine, itemCount}]` |
| GET | `/api/courses/{courseVersionId}/payload/` | 完整编译产物（上图 JSON） |
| POST | `/api/sessions/` | 创建会话。body：`{courseVersionId, mode:"L"\|"T", itemCount?:int}` → `{sessionId, attemptId, resumed:false}` |
| GET | `/api/sessions/{id}/` | 会话状态：`{status, mode, totalScore, resumeToken, eventCount}` |
| POST | `/api/sessions/{id}/events/` | 推送事件批：`{events:[...], resumeToken?:any}` → `{accepted:int, status}` |

- 创建会话时后端生成 `randomSeed`（int）与 `attemptId`（uuid），随 payload 下发。
- **恢复**：`GET /api/sessions/?status=active&courseVersionId=...` 查可恢复会话（MVP：每课程版本取最新一条 active）。前端把 `resumeToken` 连同 `sessionId` 传给引擎。
- 事件幂等：`eventId` 唯一约束，重复提交去重；`seq` 必须递增（同会话内），乱序拒绝（409）。
- 后端裁决：`itemResolved.score` 校验 ∈[0,1]；`activityFinished` 时后端以已收 `itemResolved` 的 score 均值重算 `totalScore` 作为权威值落库（与上报值并列记录，不一致记 warning）。通过门槛 MVP 不配置，只记录。

## 四、运行时事件（对齐合约 §2）

统一头：`eventId(uuid) · seq(int, 会话内 1 起递增) · ts(epoch ms) · type · payload`

| type | payload |
|---|---|
| `activityReady` | `{ itemCount }` |
| `itemStarted` | `{ index }` |
| `itemResolved` | `{ index, score, dimensions:[], attemptNumber, encounterNumber, elapsedMs, errorType?, masteryEvidence? }` |
| `activityFinished` | `{ totalScore, perItemDetail:[] }` |

`resumeToken`：引擎私有、后端不透明透传。Znawca 学习模式 = LearningSession 快照（queue/completed/records）；测试模式 = `{index}`。每次事件推送时可携带，后端存最新值。

## 五、引擎接入（UI 宿主合约，切片形态）

引擎以前端 npm 包形式被平台前端引用（vite alias `@znawca` → `src/znawca/src`），导出：

```ts
// adapter：合约适配器（push 事件由此发出）
export interface EngineEvent { eventId: string; seq: number; ts: number; type: string; payload: unknown }
export interface ZnawcaActivityProps {
  coursePayload: CourseVersionPayload;   // 第二节 JSON
  mode: "L" | "T";
  randomSeed: number;
  itemCount: number | null;
  resumeToken: unknown | null;
  onEvent: (e: EngineEvent, resumeToken?: unknown) => void;  // 编排器回调，负责 POST 后端
  onExit: () => void;
}
export function ZnawcaActivity(props: ZnawcaActivityProps): JSX.Element;
```

- 编排器（平台前端）职责：建会话、取 payload、把 `onEvent` 事件 POST 到后端（带失败重试队列）、刷新页面后用 resumeToken 恢复。
- 引擎职责：出题（复用桌面 `buildCourseQuestionSet` + 简化选题：seed 随机 sample）、呈现、评分证据（复用 `evaluateAnswer`）、发四事件。
- Activity Host（平台前端）：统一外框——标题栏、退出确认（exit 弹窗）、错误界面、主题容器；引擎内容挂进容器。

## 六、主题

平台外壳与引擎统一用 Znawca 天鹅绒绿+金主题（复制桌面 `app-shell.css` 的 :root 变量）：
`--velvet:#123b2b; --deep:#071a13; --gold:#c6a24b; --pale-gold:#f0d990; --metal:#546158; --line:rgba(209,175,89,.48)`；
标题字体 Palatino Linotype/Georgia serif，正文 Candara，答题文字 Consolas。

## 七、切片验收（闭环）

1. `POST /api/sessions` → 进入活动 → `activityReady` 落库。
2. 逐题作答：`itemStarted/itemResolved` 顺序落库，score ∈[0,1]。
3. 答完 → `activityFinished` → 后端权威 totalScore 落库 → 结果页展示。
4. 中途刷新页面 → 课程卡片显示「继续」→ resumeToken 恢复队列 → 接着答题。
5. 重复推送同一 eventId → 不重复计数。

# 以下 v0.1 增补（2026-10-06）：认证 + 开发者上传 + 界面语言

## 八、认证（Token）

- 机制：DRF TokenAuthentication（`rest_framework.authtoken`）。请求头 `Authorization: Token <token>`。
- 端点：

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login/` | 公开 | body `{username, password}` → `{token, user:{username, isDeveloper}}`；凭证错误 → 400 `{error}` |
| POST | `/api/auth/logout/` | 需认证 | 删除当前 token → 204 |
| GET | `/api/auth/me/` | 需认证 | → `{username, isDeveloper}` |

- **除 login 外所有 `/api/` 端点要求认证**，未认证 → 401。
- 开发者 = `User.is_staff`。无注册页；账号由后端 management command/ shell 创建。
- 前端：token 存 `localStorage`，每次请求带 header；任何 401 → 清 token 跳登录页。
- 会话（Session）不绑定用户（切片期单学习者语义保留，后续接 Learning State 时再绑）。

## 九、开发者课程上传

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/dev/courses/upload/` | 需认证 + **is_staff**（否则 403） | multipart 字段 `file`：课程 ZIP（≤200MB） |

- ZIP 结构：解压后 = 一个 Znawca V2 课程目录（允许 ZIP 根下包一层同名子目录）。含 `*_语言码.xlsx` + `media/` + 可选 `speech/`、根目录正误音效。
- 后端**同步**执行与 `import_znawca` 相同的导入逻辑（导入代码须从 management command 抽成可复用函数，两处共用）。
- 成功 → 200 `{imported: [{courseVersionId, title, languageCode, itemCount, reused:bool}], warnings: [str]}`（同 hash 重复导入 → `reused:true`，不报错）。
- 解析/校验失败 → 400 `{error, detail}`；超过大小限制 → 413。
- 媒体落盘路径与 command 导入一致（`media/<courseVersionId>/`）。

## 十、界面语言

- 外壳支持 5 语言：`zh-CN / en / pl / ru / ar`，默认 `zh-CN`，选择存 `localStorage`；`ar` 时根容器 `dir="rtl"`。
- 壳层文案（登录/课程列表/开发者页/顶栏/退出确认等）由前端自维护 i18n 字典；引擎 UI 文案复用 `src/znawca/src/core/localization` 的 `translate(locale, key)`。
- `ZnawcaActivityProps` 增补：`interfaceLang: Locale`（引擎 UI 消除硬编码中文，改走 translate）。
